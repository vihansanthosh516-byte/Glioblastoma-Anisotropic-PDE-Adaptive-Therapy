**Status (updated 2026-11-04):** Decision plan, not a protocol amendment or authorization to read patient data. Track A and Track C are outside scope. The LUMIERE patient run remains paused; its synthetic implementation is development infrastructure. Since this plan was drafted, a separate metadata-only Duke inventory was completed and the user-reported local archive matched its expected size and supplied MD5. The inventory did not establish final eligibility, patient-level independence, or a frozen triplet count. Exact accepted data-use/output terms and written school approval are not recorded. No MRI or mask voxels, landmark coordinates, or patient scores were read. ## Decision

Pursue **one conditional external Track B test**, with Duke as the first cohort to screen. Do not run a series of patient cohorts until one is positive. Develop and debug on synthetic cases and already saved, authorized MU/LUMIERE summaries; any new patient-voxel read needs its own gates and authorization. Reserve any genuinely independent cohort for one frozen evaluation. If Duke access, eligibility, label/QC or compute gates fail, stop the Duke patient test. One finite backup metadata screen may follow; if no cohort clears, report external validation as unavailable. UCSD-PTGBM, MU, LUMIERE and CFB are not substitutes for an untouched confirmatory cohort in this project without a new prior-use audit.

The [Duke record](https://zenodo.org/records/20548528) currently lists 61 patients, 3–18 sessions, 503 scans, relative dates, and per-session nnU-Net labels 1 necrotic core, 2 T2/FLAIR abnormality, 3 enhancing tumor, and 4 cavity. Files are restricted and the record displays **136.3 GB**. These are dataset totals, not an eligible-triplet count. [Author guidance](https://github.com/deshanyang/GBM-DIR-QA) says sessions are not aligned to one another and scan dates can be off by days. The local [external cohort screen](track_b_external_cohort_screen_2026-10-28.md) records an access resubmission as user-reported, not granted. No Duke patient-level independence or eligible cohort size is verified.

The [UCSD-PTGBM source](https://www.cancerimagingarchive.net/collection/ucsd-ptgbm/) reports 178 subjects and 243 timepoints. The local [metadata audit](track_b_ucsd_external_test_protocol.md) found 48 GBM patients with at least two visits and 63 adjacent intervals; this implies at most 15 could have three visits, before image and label checks. UCSD has already been partially exposed in a separate project side study. It is a limited exploratory fallback, not the current external target. [MU](https://www.cancerimagingarchive.net/collection/mu-glioma-post/) and [LUMIERE](https://pmc.ncbi.nlm.nih.gov/articles/PMC9755255/) have also been used in this project.

## Scientific question and claim boundary

The implemented LUMIERE candidate is a joint PDE parameter posterior plus a training-only volume trend and correlated boundary perturbations (`src/fk_hybrid_forecast.py`). It **does not** implement a learned residual or stability-shrink gate. Do not use either as the novelty claim for this candidate. [SoC-DT](https://arxiv.org/html/2510.03287) already evaluates a PDE/neural correction system on real glioma data. [GliODIL](https://www.nature.com/articles/s41467-025-60366-4) and [PREDICT-GBM](https://arxiv.org/html/2509.13360) establish other real-patient PDE/recurrence comparisons, but their recurrence-coverage numbers are not forecast Dice.

**Recommended narrow hypothesis:** On a frozen external cohort, does PDE-derived spatial shape improve next-visit tumor-core mask Dice beyond a **history-aware, matched-volume non-PDE shape rule**? The existing no-PDE arm is useful but ranks by signed distance from the **last mask only**, while the candidate uses two history masks. Its boundary perturbations also use a separate random stream. Candidate versus that existing arm can only show performance against a last-mask shape rule at matched volume; it cannot isolate the spatial PDE component.

Before choosing the primary contrast, design and test a two-history non-PDE control on development cases only. One candidate rule extrapolates registered signed-distance maps by the ratio of forecast to history interval, ranks voxels inside the same support to each shared volume draw, and uses matched boundary perturbation. Freeze its handling of tiny gaps, shrinkage, empty masks and numerical caps. Use common perturbation draws where technically possible and report a deterministic pre-boundary matched-volume sensitivity, because matching random seeds alone may not match boundary displacement fields. Promote the candidate-versus-control paired contrast to a prespecified primary test **in a new, dated cohort-specific amendment before target scoring**. Even this tests predictive systems under shared constraints, not causal PDE biology.

Keep copy-last, training-only time-aware fixed growth, shared-posterior PDE-only and a time-aware **mask-based** FiLM U-Net as strong contextual comparators. The current U-Net uses history masks, support and intervals, not MRI intensities; any MRI-based U-Net would need a separately frozen recipe. Without one, do not claim superiority over MRI-based image AI. The count model reports count metrics only. Decide in the amendment whether a second adjusted contrast against the strongest development-selected comparator is required for a stronger performance claim; report all comparators regardless. A failure, fallback or empty forecast remains in the denominator under frozen rules. One patient, not one voxel or visit, is the inference unit. If more than one triplet per patient is used, specify patient-level aggregation before reading targets.

The external endpoint would be **agreement with source-provided automated core labels**, not true tumor burden, clinical benefit or prospective scheduled-day prediction. If the model receives the realized origin-to-target interval, name the estimand *next observed visit conditional on its interval*. A fixed-day prospective forecast would require a separately supported window and data count. No positive outcome, novelty score or clinical value is promised. A new cohort alone cannot raise novelty to 7–8/10; that would require a distinct implemented mechanism, a current prior-art audit and a prespecified ablation that supports it.

## Compute and code corrections to carry forward

The LUMIERE four-analysis projection of roughly **557–931 wall-clock hours** is a scenario, not a bound and not a Duke estimate. The projection already counts 28 full and **112 inner cross-fitted calibration-only** forecasts per full LUMIERE analysis; earlier draft language saying inner cross-fitting was excluded was incorrect and has been corrected. The central-gap metadata subset has 22 patients, while the old projection counts that run at 28; this overstates that component. Synthetic time per U-Net step varied about twofold across sessions, so re-time any new protocol. Even a LUMIERE primary-only run would be roughly 197–349 hours under the existing scenarios, before new overhead; it remains paused.

`src/fk_lumiere_protocol.py` presently accepts a caller-supplied PDE provider, model recipe, bootstrap count and fold map for synthetic testing. The real-data entry point must reject overrides that differ from a pre-run seal. Max-T currently adjusts four within-run contrasts, **not** the three prior scenarios plus central-gap refit as independent confirmations. Treat robustness runs descriptively unless a joint family is predeclared. The current post-run hash writer is not a pre-run freeze and does not hash patient inputs.

4. **Independent skeptic:** review all three products for leakage, license overclaim, reused-patient exposure, comparator weakness, multiplicity and post-hoc choices. Resolve disagreements in the decision record before adoption.
