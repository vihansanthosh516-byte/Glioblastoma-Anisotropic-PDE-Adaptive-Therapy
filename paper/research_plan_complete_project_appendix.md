# Reproduction appendix: GBM Tracks A, B, and C

This protocol preserves the three prior GBM tracks as equally important core work. It specifies separate questions and endpoints without stating project results or predicting a direction. Exploratory model development and dataset evaluation have already occurred in each area; earlier test groups are not fresh confirmatory sets. The plan is conditional: source permissions, cohort manifests, and unresolved settings in the protocol manifest must be verified and frozen before affected analyses.

## Shared data and evaluation rules

1. Keep molecular, MRI, clinical-association, and simulation outputs separate. No verified patient-level join connects the atlas to MRI cohorts.
2. Use donor/patient as the split and resampling unit. Resolve sample, assay, visit, and patient identifiers using source documentation.
3. Record source release, exact files, labels, preprocessing, exclusions, and file-level terms. Public download does not by itself permit cloud transfer or redistribution.
4. Fit all preprocessing, feature selection, parameter tuning, calibration, and predictive variance using training folds only. Freeze eligibility, partitions, seeds, grids, estimands, and failure rules before examining evaluation outcomes.
5. Previously used atlas and MRI evaluation groups remain exploratory. Do not relabel them as fresh confirmatory tests by changing folds or metrics.

## Procedure

### 1. Track A — expression classification, gene panels, and matched spatial evaluation

**Questions.** Among source-identified donors, how do bounded attention and graph models compare with fixed classifiers for dissociated-cell GBM Core/Periphery labels? Where source labels, exact panel files, matched specimens, and reuse terms permit, how do fixed gene panels classify measured spatial labels in specimens held out from model fitting?

1. Resolve the UCSC `multiomic-gbm` release, files, cell labels, donor/sample aliases, and file-level reuse terms. The article and Cell Browser establish public data access, but the exact reuse license for each export was not verified. Do not use atlas files in cloud compute or redistribute them while source terms remain unclear. If access, terms, or donor identities cannot be verified, retain the track as a documented research question and stop model scoring.
2. For dissociated cells, define the target as GBM Core versus GBM Periphery. Exclude “NormalBrain” from this target because retained cells include other CNS tumor diagnoses. Include donors only when a verified source map and both labels support a donor-held-out comparison. Do not report unresolved `ID1` groups as unique people.
3. Compare the attention-gated gene model (the historical source implementation uses up to 2,500 features), PCA/logistic regression, and an exact source-identified gene panel. Use a train-derived 50- or 200-feature sparse panel only if the manifest explicitly selects that method and genes are selected inside each training fold. A source-published panel means the named 40-gene anatomical panel or 348-gene Xenium panel; verify exact feature files and platform coverage before use. Do not invent panel content or apply genes absent from an assay.
4. Include graph attention only as an inductive method: build the training graph from training data; connect held-out cells to training nodes with expression-derived edges; exclude tissue labels, region/transition annotations, patient-identity edges, and test-to-test graph construction. Fit embeddings and graph choices within training folds. If this protocol cannot be implemented with verified inputs, report the graph comparison as not estimable instead of using historical label-leaking graph features.
5. Freeze donor-grouped outer folds and training-only model selection. Historical grouped test donors were scored repeatedly and earlier feature selection used the full dataset, so any reuse is exploratory, not confirmation. Report per-donor macro-F1, class metrics, paired donor differences, donor bootstrap intervals, exclusions, and fold support. Undefined class support remains undefined; do not reassign donors.
6. Evaluate spatial transfer as a separate endpoint only where specimens have source-measured spatial labels and matched identities. Hold out the entire patient/specimen from model fitting; evaluate only spatial cells/spots and gene features actually measured in that specimen. Do not use dissociated Core/Periphery predictions as spatial ground truth or derive a spatial target from predicted subtype pseudozones. Report specimen-level metrics and valid specimen composition. If the sample crosswalk, measured labels, panel coverage, or terms fail, stop this component.

**Limits.** The atlas notes report separate single-cell and spatial resources, but local source release, export terms, unique donor mapping, and panel-to-platform files were not established. The published anatomical and Xenium panels are distinct from the repository’s model-selected feature input. Spatial evaluation requires actual specimen-level spatial labels and a held-out tissue design.

### 2. Track B — MRI mask/volume forecasting and recurrence-location comparison

**Questions.** For longitudinal postoperative MRI, how do reaction-diffusion mask forecasts compare with persistence and geometric growth, and how do measurement-aware log-volume forecasts compare with fixed predictive baselines? Separately, on rights-cleared source data, how does an MRI recurrence-risk map compare with an equal-volume 15 mm geometric expansion in coverage of subsequently observed recurrence?

1. Keep endpoints distinct. Mask/volume analyses use longitudinal scans; recurrence analysis uses preoperative MRI inputs and later recurrence masks. Do not use `src/40_spatial_recurrence_mapper.py` subtype pseudozones as spatial recurrence truth. Score only source-observed recurrence labels. The 15 mm comparator is a geometric surrogate, not a radiotherapy plan or treatment comparator.
2. **MU local forecast data.** Use exact MU-Glioma-Post v1 image, segmentation, and clinical files locally under the collection’s listed CC BY 4.0 terms and required citation/policy. Validate source patient IDs, visit dates, mask orientation/geometry, voxel dimensions, label map, and scan-to-mask joins. Define tumor core volume from NETC+ET labels 1 and 3 times physical voxel volume; do not mix SNFH edema or resection-cavity label 4 into this measure. Restrict to source-confirmed GBM if the estimand is GBM-specific; otherwise name the mixed-glioma population. Reconcile eligibility denominators before setting folds.
3. **Mask forecasting.** Define eligible cases as consecutive within-patient scans with verified dates, documented interval, and nonempty input core. Forecast the later mask from the earlier scan. Compare the positivity-preserving reaction-diffusion solver with input-mask persistence and geometric reshaping using a training-fold population median log-growth rate. The historical grid is rho {0, .01, .03, .1, .2}, d {.003, .01, .03, .1, .3}, and sharpening r {1, 10}; retain it only if the manifest confirms the same solver, units, folds, and data representation. Select settings using training patients only. Score Dice on matched patient pairs, aggregate within patient, and report paired uncertainty, grid-edge selections, numerical clamps, and failures. Existing MU folds and outcomes have been used; any rerun is exploratory.
4. **Volume forecasting.** For positive core volume V_ij, define y_ij = log(V_ij) and time t_ij as verified scan day. With x_ij as latent log volume, set y_ij = x_ij + e_ij, where e_ij is zero-mean normal scan error with variance sigma_e squared; set x_i,j+1 = x_ij + g_i times delta-t plus eta_ij, where eta_ij has variance sigma_w squared times delta-t; and let g_i be normal with population mean mu_g and variance tau_g squared. Here g_i is net change under the observed care pathway, not untreated growth; sigma_w is unexplained process variation, not biological variability. Use an exact diffuse initial level independent of scan error. The first observation is absorbed into that initial level and does not identify sigma_e. Marginalize the random slope in the linear-Gaussian likelihood and estimate population parameters on training patients only. Record parameter transforms, Jacobian, priors/units, optimizer, and sensitivity settings in the protocol manifest.
5. Estimate scan error only through contrasts across repeated observations. The Abu Khalaf repeatability study is external and not matched to MU core masks; its conversion is not a measured MU error scale. If a source-based scale and applicability cannot be defended, use declared sensitivity settings and do not claim scan error was separated from net volume change. The forecast target is the observed next log volume; include parameter and observation uncertainty in its predictive density.
6. Use the same eligible patients and forecast occasions for every method, scoring only forecasts from the third usable scan onward. Compare persistence and the training-patient median slope; add an M1v baseline with predictive variance a + b times delta-t + c times delta-t squared, fit only on training-fold rolling residuals. Also compare state-space ablations without random slope, with scan error fixed at a predeclared prior median, and with process noise zero. A gain over constant-variance baselines alone is not evidence of measurement-error separation.
7. Before patient fitting, run recovery and misspecification checks on verified visit schedules. Draw truths both from declared priors and predeclared off-prior settings; include changing error by volume, scan-order bias, treatment-related slope changes, and floor/censoring scenarios only after fixing the real-data volume rule. Report coverage with Monte Carlo uncertainty, bias, interval width, visit-spacing distribution, and failures. A wide interval that covers but exceeds the central 80% prior range does not establish identification. Profile the parameter pairs (tau_g, sigma_e), (sigma_w, sigma_e), and (tau_g, sigma_w) with a prior-free marginal likelihood and a separately labeled prior-informed surface; call the surface flat when the prespecified contour reaches a grid edge.
8. Apply this provisional Step 0 stop rule: stop claims of separately identified measurement/process/slope variance if 90% interval coverage for scan error falls outside 0.80–0.97 in any simulation setting, median scan-error interval width exceeds the central 80% prior range, or more than 10% of fits fail. Require at least 50 eligible patients with three or more dated positive core-volume scans for an inferential five-fold comparison; otherwise report descriptive feasibility only. These cutoffs are proposed project decision rules, not validated literature or clinical standards; justify and freeze them before patient outcomes. Do not proceed with a variance fixed at a selected value without a dated protocol amendment.
9. **Recurrence-location comparison.** Use only directly source-obtained MRI and follow-up recurrence masks whose exact file terms and provenance are documented. Construct the 15 mm comparator by expanding the preoperative core in physical space within the documented brain mask. Threshold the model risk map to the same target volume, then score coverage of enhancing recurrence (ET label 3) and all recurrence (labels 1–3) separately. Lock registration, orientation, target definition, exclusions, and patient folds. Do not use unverified PREDICT-GBM derivative packs or UCSF-ALPTDG labels; the latter requires a DUA and prior cloud-transfer permission is unresolved. If no rights-cleared cohort and eligible held-out partition can be established, retain this endpoint in project scope but do not score it.
10. Report patient-level paired Dice or recurrence-coverage differences, observed-volume predictive log scores, predictive interval coverage/calibration, denominators, exclusions, fit failures, prior sensitivities, and whether each endpoint was estimable. Keep MU, LUMIERE, and RHUH separate because populations, labels, and measurement pipelines differ.

**Data and model limits.** MU’s local manifests give different denominators for different analyses, so reconcile the patient-by-visit inclusion manifest before use. MU mixes diagnoses; a GBM-specific analysis needs a verified diagnosis filter. Historical inverse PDE fits reached search bounds in many cases, and scan-rescan error is not measured in the MU cohort. LUMIERE and RHUH require separate file-level terms, and prior use means neither is a pristine holdout.

### 3. Track C — two-population adaptive therapy, optimal-control/RL, and MGMT association

**Questions.** Under declared assumptions, how do a two-population adaptive schedule and fixed TMZ schedule compare, and how do existing optimal-control/RL policies compare with fixed and simple-rule schedules in a separate simulator? Separately, what observational association exists between verified MGMT status and progression time? None estimates an individual causal treatment effect.

1. **Two-population model.** Use the source-defined sensitive/resistant spatial simulator in `src/44_adaptive_therapy.py`. Documented settings include a 100 by 100 grid, 1 mm spacing, 0.1-day step, 5,000 steps/500 days, two-clone logistic competition and mutation, and Hill-form drug kill. Compare the fixed five-days-on/23-days-off schedule with adaptive dosing; do not call the fixed schedule continuous maximum dosing. Adaptive thresholds are off at 0.80 and on at 1.00 baseline/peak in the inspected settings, but a conflicting threshold comment must be reconciled before locking the run. Paired arms use identical initial clone fields. Use MU-fitted growth only if its source lineage and diagnostics are documented; fitted growth does not make kill response patient-measured.
2. Use only the source-defined Emax/growth sweep documented in the kill-rate configuration: 100, 250, 500, 1,000, 2,000, 4,000, and 8,000. Record fitness cost, mutation, initial clone fields, dose reset, thresholds, and code revision. No global random seed is asserted; reconcile comments/defaults and record required seeds before execution. Report modeled burden, progression time/censoring at the code-defined threshold, resistant fraction, and cumulative modeled dose across all settings. Model dose is not clinical dose.
3. **Optimal-control/RL model.** Keep scripts 64–68 as a separate single-population simulator family. Documented runs differ: script 64 defines a 20-case virtual cohort and seed 42; the script 66 evaluation describes a separate 30-scenario Latin-hypercube set. Do not combine their denominators or call them one evaluation. The family includes a 64-cubed domain, daily decisions, five PDE substeps/day, a 90-day treatment horizon, four actions (off, chemotherapy, radiation, combination), and a budget matched to the Stupp-schedule AUC in the equal-budget arm. Compare only policies that share one verified simulator, cohort, budget, and evaluation split: source-defined Stupp-like fixed, capped-volume heuristic, PPO, and DAgger/oracle-reference policies. The oracle is an upper-bound reference, not an implementable policy. Any fitted-growth “real_test” remains a simulation because kill values are assumed. The time-to-progression extension continues untreated simulation through day 365 and defines progression at modeled volume at least 1.4 times nadir; this is not clinical RANO.
4. Freeze simulator generation, cohort mode/IDs, PDE regime, action intensities, modeled budget, policies/rewards, training/evaluation split, seeds, checkpoint hashes, and scoring rules. Compare policies on common simulated cases; report modeled burden, progression, exposure/toxicity, and censoring. If seeds, checkpoints, or split lineage cannot be reconstructed, report the comparison as not reproducible and do not produce a fresh score. Equal modeled AUC does not establish equal clinical efficacy or toxicity.
5. **Observational MGMT association.** Use the MU clinical workbook only after its version, MGMT codebook, diagnosis, progression-time origin, event/censor fields, and missingness are documented. Restrict groups to source-verified code meanings; do not infer code meaning from a local script alone. Predefine the association estimand and event, censor, and competing-risk treatment. Summarize association with a survival method and uncertainty, denominators, and exclusions. If event time origin or death-before-progression handling remains unresolved, do not estimate the association. Keep this analysis separate from simulations and never translate MGMT into an assumed resistant fraction or treatment effect.

**Limits.** Script 44’s drug effects are assumptions and its runs use fitted growth rates, not fitted drug response. The RL family uses a different state, assumptions, policies, cohorts, seeds, and endpoints. No simulated policy establishes human efficacy, patient-specific treatment benefit, or clinically equivalent dose comparison.

## Planned synthesis

1. Present one section for each core track and separate sub-endpoints within each track. For each, state source, analysis unit, estimand, method, comparator, metric, uncertainty, evidence type, and limitation.
2. Report which access, data-integrity, model-fit, and evaluation gates passed. Do not fill an unresolved denominator, label, license, panel, seed, or parameter grid by assumption.
3. Describe analysis history plainly; do not quote prior result values or write them as planned outcomes.
4. Report null, adverse, mixed, unstable, non-identifiable, or non-estimable outcomes without selecting a favorable setting. Do not claim cross-track patient fusion, spatial accuracy from dissociated labels, clinical treatment effects, or a validated digital twin.

## Feasibility and limits

Future analyses may proceed after this plan is frozen and each source, provenance, and protocol gate closes. Restricted or unresolved components stop at their stated gates. No single verified cross-track dataset or evaluation set supports all endpoints. Reused groups remain exploratory; several derivative-data rights are unresolved; MU denominators differ by workflow; the measurement-error model may be weakly identified; Track C effects are assumed; and MGMT field definitions require verification.
